# Live demo guide

A step-by-step script for demonstrating the application and running the test cases live, e.g. in a viva or interview.

## 1. One-time setup (~10 min)

Python 3.11+ is required.

**Windows (PowerShell)**

```powershell
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python -m playwright install chromium
pytest -q                      # expect: 558 passed, 2 skipped
```

If PowerShell refuses to run `activate`, run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once.

**macOS / Linux**

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
python -m playwright install chromium
pytest -q
```

Optional: `python -m playwright install firefox webkit` lets the two cross-browser cases run instead of being skipped.

## 2. Demo the application (~3 min)

Terminal 1:

```bash
uvicorn app.main:app --reload --port 8765
```

> On Windows, `WinError 10013` on port 8000 means the port is reserved (Hyper-V/WSL/Docker). Use another port such as 8765.

Open <http://127.0.0.1:8765>:

| Step | Action | Point out |
|---|---|---|
| 1 | Register with password `hotel` | Clear validation message (BVA/ECP-tested) |
| 2 | Register properly (`Hotel@2026`, age 21, 10-digit mobile) and sign in | Header shows the signed-in guest |
| 3 | Search 2 → 5 Nov 2026 | Four room types with the price for the stay incl. GST |
| 4 | Deluxe → Select, Adults 2, Get price | **₹12,600.00** — the same value the E2E test asserts |
| 5 | Promo `WELCOME10`, Get price | Discount applied (decision-table rules) |
| 6 | Reserve, pay with `4111 1111 1111 1111`, 12 / 2028, CVV 123 | Status **CONFIRMED** |
| 7 | Pay with `4111 1111 1111 1112` instead | Rejected by the Luhn check |
| 8 | Cancel | **CANCELLED**, 100 % refund (rule R3, ≥ 7 days ahead) |

API documentation: <http://127.0.0.1:8765/docs> (admin `admin@hrrs.test` / `Admin@123`, demo credentials only).

## 3. Run the test cases live (~5–8 min)

Terminal 2 (same folder, venv active):

```bash
python tools/live_demo.py
```

It runs 11 stages and waits for **Enter** before each one; every test case prints its ID, objective, result and duration as it runs.

| Stage | Suite | Cases |
|---|---|---|
| 1 | Smoke | 5 |
| 2 | Boundary value analysis | 161 |
| 3 | Equivalence partitioning | 85 |
| 4 | Decision tables + cause-effect graph | 53 |
| 5 | State transition | 40 |
| 6 | White-box (statement → MC/DC, basis paths, loops, data flow) | 43 |
| 7 | Integration (incl. 20-thread race) | 31 |
| 8 | System, negative, contract, security | 46 |
| 9 | **End-to-end in a visible browser** | 15 |
| 10 | Acceptance (Gherkin) | 6 scenarios |
| 11 | Full regression with coverage + HTML report | all |

Options: `--auto` (no pauses), `--stage 9` (start at a stage), `--headless` (no browser window).

Individual commands:

```bash
pytest -q --tc tests/unit/test_decision_tables.py
pytest -q --tc -m smoke        # also: security, e2e, regression, recovery, performance
```

Slow, visible browser tests:

```powershell
$env:HRRS_HEADED="1"; $env:HRRS_SLOWMO="700"; pytest -q --tc -m e2e      # Windows
```

```bash
HRRS_HEADED=1 HRRS_SLOWMO=700 pytest -q --tc -m e2e                       # macOS / Linux
```

## 4. Plant a bug and watch it get caught (~1 min)

1. In `app/domain/cancellation.py`, change `RefundDecision(50,` to `RefundDecision(60,` and save.
2. `pytest -q --tc tests/unit/test_decision_tables.py` → TC-CAN-DT-004, 013, 014, 015 **FAIL** (expected 50 %, got 60 %).
3. Change it back to `50` and re-run → all green.

## 5. Show the evidence

- `reports/test_report.html` — pytest HTML report (regenerated by stage 11)
- `reports/coverage_html/index.html` — line-by-line coverage
- `deliverables/HRRS_Test_Results_Dashboard.html` — searchable results for all 554 cases

## Troubleshooting

| Symptom | Fix |
|---|---|
| `pytest` / `uvicorn` not recognised | Activate the venv again |
| `No such file: requirements.txt` | You are not in the project folder |
| Browser does not open in stage 9 | `python -m playwright install chromium` |
| Bookings vanish after restart | The app uses an in-memory DB; set `HRRS_DB=hrrs.db` to persist |

Tests start their own private server on a free port, so they can run while the demo app is open.
